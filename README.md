**Conventional Commits**

---

## 1. 커밋 메시지 기본 형식  
```plaintext
<타입>: <변경 사항 요약>

<본문 - 선택적>
<관련 이슈 - 선택적>
```

---

## 2. 커밋 메시지 타입(Type)  
각 커밋의 목적을 명확히 하기 위해 다음과 같은 타입을 사용합니다.

| 타입      | 설명 |
|-----------|--------------------------------------|
| **feat**  | 새로운 기능 추가 |
| **fix**   | 버그 수정 |
| **docs**  | 문서 수정 (README.md 등) |
| **style** | 코드 스타일 변경 (포매팅, 세미콜론 추가 등) |
| **refactor** | 코드 리팩토링 (기능 변경 없음) |
| **perf**  | 성능 개선 |
| **test**  | 테스트 코드 추가/수정 |
| **chore** | 기타 변경 (빌드 설정, 패키지 업데이트 등) |
| **ci**    | CI/CD 관련 설정 변경 |
| **revert** | 이전 커밋 되돌리기 |

---

## 3. 커밋 메시지 예제  

### ✅ 기능 추가 (feat)  
```plaintext
feat: 사용자 로그인 기능 추가

이메일과 비밀번호를 입력하여 로그인할 수 있도록 로그인 API 구현.
JWT를 사용하여 인증 기능 추가.
```

### ✅ 버그 수정 (fix)  
```plaintext
fix: 로그인 시 잘못된 비밀번호 오류 메시지 수정

비밀번호가 틀릴 경우, 정확한 오류 메시지를 반환하도록 수정.
기존 메시지: "에러 발생" → 수정 메시지: "비밀번호가 일치하지 않습니다."
```

### ✅ 문서 수정 (docs)  
```plaintext
docs: README에 설치 방법 추가

프로젝트를 처음 시작하는 개발자를 위해 설치 가이드를 추가함.
```

### ✅ 코드 스타일 변경 (style)  
```plaintext
style: 코드 포매팅 적용

ESLint 규칙에 맞춰 자동 정렬을 수행하고, 불필요한 공백 제거.
```

### ✅ 코드 리팩토링 (refactor)  
```plaintext
refactor: 회원가입 로직 개선

중복 코드 제거 및 서비스 계층을 분리하여 코드 가독성을 향상시킴.
```

### ✅ 성능 개선 (perf)  
```plaintext
perf: 데이터베이스 쿼리 최적화

불필요한 JOIN을 제거하고 인덱스를 활용하여 조회 속도를 개선함.
```

### ✅ 테스트 코드 추가 (test)  
```plaintext
test: 회원가입 API 테스트 코드 추가

회원가입 시 정상적으로 동작하는지 검증하는 단위 테스트 작성.
```

### ✅ 기타 변경 (chore)  
```plaintext
chore: ESLint 및 Prettier 설정 추가

팀 내 코드 스타일을 통일하기 위해 코드 포매팅 설정 파일 추가.
```

### ✅ CI/CD 설정 변경 (ci)  
```plaintext
ci: GitHub Actions CI/CD 워크플로우 추가

PR 생성 시 자동으로 테스트가 실행되도록 CI 설정 추가.
```

### ✅ 이전 커밋 되돌리기 (revert)  
```plaintext
revert: 회원가입 API 변경 사항 롤백

이전 커밋(abc123)을 되돌리고 기존 코드로 복구함.
```

## 4. 추가적인 규칙  

### ✨ 제목(첫 줄) 작성 규칙  
1. **명령형 동사 사용**  
   - `Add` ❌ → `feat: 추가` ✅  
   - `Fixed` ❌ → `fix: 수정` ✅  

2. **50자 이내로 작성**  
   - 너무 길면 가독성이 떨어짐.  

3. **마침표(.) 사용하지 않기**  
   - `feat: 로그인 기능 추가.` ❌ → `feat: 로그인 기능 추가` ✅  

### ✨ 본문 작성 규칙 (선택)  
- **어떤 변경을 했는지 구체적으로 설명**  
- **필요하다면 왜 변경했는지 추가 설명**  
- **관련된 이슈 번호 추가 (예: `Closes #123`)**  

```plaintext
fix: 로그인 시 잘못된 비밀번호 오류 메시지 수정

비밀번호가 틀릴 경우, 정확한 오류 메시지를 반환하도록 수정.
기존 메시지: "에러 발생" → 수정 메시지: "비밀번호가 일치하지 않습니다."

Closes #45
```

## 5. 결론  
- **일관된 커밋 메시지는 코드 변경 내역을 쉽게 이해하고 유지보수하는 데 큰 도움이 됨**  
- **Conventional Commits 규칙을 따르는 것이 가장 일반적이며, 팀 내에서 별도의 컨벤션을 정해도 됨**  
- **커밋 메시지는 깔끔하고 명확하게 작성하는 것이 중요!** 🚀
